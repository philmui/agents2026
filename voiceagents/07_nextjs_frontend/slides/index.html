Concept · transport

Why WebRTC, not WebSocket

Chat wants every message, in order (TCP). A WebSocket rides TCP.
A call wants to stay live: skip a lost slice, do not freeze (UDP). WebRTC rides UDP.
WebRTC also gives echo cancel + NAT traversal for free.
THE RULE WebRTC for browsers, WebSocket for servers. A server has no mic and a public address, so it uses a WebSocket (modules 02-05). A browser needs low-latency media, so it uses WebRTC.

The whole handshake

Browser → backend → OpenAI

Solid = request, dashed = reply. The real key never leaves the backend.

Concept · secrets

The browser never sees the real key

Real sk- key = your credit card. Lives only on the server.
ek_ token = a $5 gift card that self-destructs in a minute. Safe for the browser.
CAUTION Anything named NEXT_PUBLIC_* is baked into the browser bundle. Put only non-secrets there (like the token URL). The OPENAI_API_KEY stays in module 06's server .env.

Path 1 · recommended

The SDK: three objects, one connect

import { RealtimeAgent, RealtimeSession } from "@openai/agents/realtime";

const ek = await fetchEphemeralToken();          // ask OUR backend

const agent = new RealtimeAgent({
  name: "Voice Tutor",
  instructions: "Friendly tutor. Keep answers short and spoken.",
  voice: "marin",                                // chosen ONCE
});

const session = new RealtimeSession(agent, {
  model: "gpt-realtime-2.1",                     // GA name (not -2)
  transport: "webrtc",
});
await session.connect({ apiKey: ek });           // ek_ only

connect() asks for the mic, does the WebRTC handshake, and plays the reply.

Path 1 · the sharp edges

Two things the SDK will not forgive

MODEL Use gpt-realtime-2.1. The name gpt-realtime-2 is the older DataCamp label.
VOICE The voice is set once on the agent and cannot change after the first audio.
CAUTION Wire listeners before connect() so you never miss the first update. And call session.close() on unmount, or the mic light stays on.

Path 1 · the transcript

One event carries the whole conversation

session.on("history_updated", (history) => {
  setTranscript(flatten(history));   // {role, text, done}
});

session.on("audio_interrupted", () => {
  // you talked over it: barge-in
});

session.mute(true);   // stop sending mic
SHINES The SDK keeps the running history; you just render it.
CAUTION transcript is null until recognition catches up. A line renders empty for a beat, then fills. Treat it as streaming until status !== "in_progress".

Path 2 · how it really works

Raw WebRTC: seven steps, no SDK

const pc = new RTCPeerConnection();                       // 1 engine
pc.ontrack = (e) => audioEl.srcObject = e.streams[0];     // 2 hear it
const mic = await navigator.mediaDevices.getUserMedia({ audio: true });
mic.getTracks().forEach((t) => pc.addTrack(t, mic));      // 3 send mic
const dc = pc.createDataChannel("oai-events");            // 4 events
const offer = await pc.createOffer();                     // 5 our menu
await pc.setLocalDescription(offer);
const res = await fetch(`${CALLS_URL}?model=gpt-realtime-2.1`, {
  method: "POST", body: offer.sdp,                        // 6 raw SDP
  headers: { Authorization: `Bearer ${ek}`, "Content-Type": "application/sdp" },
});
await pc.setRemoteDescription({ type: "answer", sdp: await res.text() }); // 7

Path 2 · the sharp edges

Three raw-path gotchas

NAME The data channel must be exactly "oai-events". A different name = no events.
BODY POST the raw SDP text with Content-Type: application/sdp. Do not JSON-stringify it.
AUTH Send Authorization: Bearer ek_... to /v1/realtime/calls. Never the real key.

Concept · the events

Watch the exact event names

response.output_audio_transcript.delta
assistant words, streaming
conversation.item.input_audio_transcription.completed
your words, final
CAUTION The assistant audio bytes event is response.output_audio.delta (base64 in delta), not response.audio.delta. With WebRTC ontrack plays audio for you, so you rarely touch bytes, but the name trips everyone up.

What you learned

Recap: safe browser voice in two ways

WebRTC, not WebSocket, for live media in the browser.
ek_ token from module 06; the real key never ships.
SDK = agent + session + connect. Raw = SDP + oai-events.
REMEMBER Model is gpt-realtime-2.1. Voice is set once. Data channel is "oai-events". Offer body is application/sdp. Audio-bytes event is response.output_audio.delta.

The one idea to remember

Browser → ek_ token → WebRTC → voice in, voice out
1The browser is never trusted with the real key. It borrows a one-minute ek_ from your backend.
2The SDK is just tidy WebRTC. Under it: a mic, a data channel, and an SDP swap you can write by hand.
