The one idea

It is a conversation between two computers

Open one long-lived connection: a session.
Trade small JSON messages: events.
Send any time, receive any time: an event loop.
session
+ events
= Realtime API

No audio in this module. We connect, configure once, and learn to read the event stream. Reading events is how you debug everything later.

The vocabulary

Seven words, one protocol

Concept What it does When it matters
SessionOne WebSocket that stays openHolds settings + history
WebSocketTwo-way pipe, either side pushesLow-latency back-and-forth
EventOne JSON object with a typeThe only thing on the wire
Client eventA message you sendYou configure or drive
Server eventA message the API sends youYour window into the API
Event loopSend-any-time, receive-any-timeNo fixed request order
session.updateConfigures the sessionRight after connecting

Why a WebSocket

Letters vs a phone call

HTTP: one request, one reply, done.
Like mailing a letter. Fine for a page, clumsy for a live chat.
WebSocket: line stays open, both talk.
Like a phone call. One open session either side can push to.
CAUTION Use wss://, not ws://. The extra s is TLS encryption, exactly like https vs http. Your API key rides this connection, so it must be the secure form.

The handshake · read top to bottom

Connect, then trade four messages

Your code            Realtime API
   |                       |
   |==== WS connect =====> |   Authorization: Bearer
   |                       |
   | <=== session.created =|   id + defaults
   |                       |
   |==== session.update ==>|   instructions
   |                       |
   | <=== session.updated =|   config accepted
   |                       |
   |   ( session stays open )
CLIENT→ Connect the WebSocket
←SERVER session.created
CLIENT→ session.update
←SERVER session.updated

Four beats. In a real app the session keeps trading events; our demo stops here.

Everything is a typed message

Events flow in two directions

You send (client)

OUT session.update
OUT input_audio_buffer.append
OUT response.create

You receive (server)

IN session.created
IN session.updated
IN error

Read event["type"] first, always. Later modules add audio events on this same loop.

The library · websocket-client

Four callbacks are the whole program

import websocket  # the "websocket-client" package

def on_open(ws):        # ONCE, when connected
    ...                 #   -> send session.update
def on_message(ws, m):  # EVERY server event
    ...                 #   -> parse + print (the loop)
def on_error(ws, e):  ...
def on_close(ws, c, r): ...

ws = websocket.WebSocketApp(
    WS_URL,
    header=[f"Authorization: Bearer {KEY}"],
    on_open=on_open, on_message=on_message,
    on_error=on_error, on_close=on_close,
)
ws.run_forever()   # connect, then loop
header= is singular and takes a list of "Name: value" strings, not a dict.
run_forever() connects, then blocks, calling on_message for each event until close.

The one client event we send

session.update: configure, then stop

import json

SESSION_UPDATE = {
    "type": "session.update",
    "session": {
        "type": "realtime",   # normal session
        "instructions": "Friendly class helper.",
        "output_modalities": ["text"],  # no audio
    },
}

def on_open(ws):
    # dict -> JSON text -> onto the socket
    ws.send(json.dumps(SESSION_UPDATE))
CAUTION The session object carries its own "type". For speech/text it is "realtime"; transcription uses "transcription" (Module 03). Omitting or mis-typing it triggers an error event.

The superpower of the whole course

on_message: print, then react

def on_message(ws, message):
    event = json.loads(message)          # text -> dict
    etype = event.get("type", "")  # read type
    print(etype)                          # your window

    if etype == "error":                  # API rejected
        print(event["error"])             # what + why

    if etype == "session.updated":        # accepted
        ws.close()                        # demo done
HABIT When audio or tools misbehave later, print the event stream first.
error events carry code + message. A 401 means a bad key or free tier.

Two facts that bite

GA changed two things

Model is gpt-realtime-2.1
Chosen in the URL: ?model=gpt-realtime-2.1. Old DataCamp name was gpt-realtime-2.
No OpenAI-Beta header
The beta needed OpenAI-Beta: realtime=v1. At GA it is gone. Send only Authorization.
REMEMBER The only required header is Authorization: Bearer <key>. Optionally add OpenAI-Safety-Identifier (a hashed user id) for production abuse tracking.

What you learned

Recap: sessions, events, the loop

Session
One long-lived wss:// WebSocket that holds your settings and history.
Events
Typed JSON: client events you send, server events you receive.
The loop
WebSocketApp + on_open + on_message; run_forever() drives it.
REMEMBER Handshake = connect → session.created → session.update → session.updated. Model is gpt-realtime-2.1; no OpenAI-Beta header. Reading the event stream is how you debug every later module.

The one idea to remember

one session  +  many events  =  the Realtime API
