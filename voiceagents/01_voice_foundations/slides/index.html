Concept 1 · Analog sound

Your voice is a pressure wave

Vocal cords push air; the push spreads as a wave.
A mic membrane rides that wave and makes a smooth voltage.
Smooth = analog: a value at every instant, infinitely fine.
THE PROBLEM Computers store lists of numbers, not "infinitely many" values. So step one is turning this smooth wave into a list. That step is sampling.

Concept 2-3 · Sampling & the rate

Measure the wave 24000 times a second

Sample: one measurement of the wave's height.
Sample rate: samples per second, in hertz.
This course uses 24000 Hz (24 kHz).
CAUTION Record at the wrong rate and 24 kHz playback sounds chipmunk-fast or slow-motion. audio_config.py sets SAMPLE_RATE = 24000 in one place so it never drifts.

Concept 4-5 · PCM16 & mono

Each sample is a 16-bit integer

PCM16: whole number -32768..32767. 0 = silence, big = loud.
16 bits = 2 bytes per sample. This one fact drives all the math.
mono = one channel, one list of numbers.
shape : (72000,)   # 3s x 24000
dtype : int16      # PCM16
first 10: [0, 1129, 2244, 3329,
           4370, 5353, 6265, ...]

Concept 6 · base64

Rewrite bytes as text for the wire

Protocols carry text, not raw binary.
base64 uses 64 safe chars: A-Z a-z 0-9 + /
raw = chunk.tobytes()        # 2400 bytes
b64 = base64.b64encode(raw).decode()
# -> "AABpBMQIAQ0SEek..."  (later: JSON)
CAUTION base64 grows data ~33%. It changes the encoding, not the audio, and it is not compression. Decoding returns the identical bytes.

Concept 7 · The pipeline

Analog sound becomes text on the wire

Play it back by running every arrow in reverse: base64 → bytes → PCM16 → speaker.

Concept 7 · The money math

48 KB per second, in each direction

24000 samp/s × 2 bytes
= 48000 bytes/s (~46.9 KB/s)
A conversation streams this both ways at once.
WHY IT MATTERS One big HTTP request cannot do this: you would finish talking, upload, wait, then hear a reply. Live voice needs a persistent, two-way connection streaming small chunks.

Concept 8 · Transports

Four ways the audio travels

They differ by duplex (both ways at once?) and by environment (server, browser, phone line).

Concept 8 · PSTN

The old phone network still matters

PSTN = the century-old telephone network.
Phone audio is G.711 / mu-law at 8 kHz, not 24 kHz PCM16.
In the API that is audio/pcmu (vs audio/pcm for web).
CONTEXT ONLY We do not build a phone bridge here. But "let people call my agent" is a real, separate integration, and this is why the API even offers a non-PCM audio format.

Concept 9 · Real time

"Real time" means a latency budget

Real time is not zero delay; it is small enough to feel natural.
Humans notice lag past roughly 250-300 ms.

Every stage adds milliseconds. Streaming, turn detection, and low-latency settings all exist to stay in budget.

What you learned

Recap: numbers, text, transports, latency

Audio = 24000 PCM16 ints/sec, mono.
base64 = safe text framing (~33% bigger, loss-free, not compression).
Transports: HTTP, WebSocket, WebRTC, PSTN.
REMEMBER ~48 KB/s each way forces a persistent two-way connection. Assistant audio = response.output_audio.delta. The browser never sees the real key. Nearly every later choice is a latency choice.

The one idea to remember

Voice = 24000 PCM16 numbers / sec → base64 → a live socket
1Once you can capture audio in the right shape, the API is just "put these bytes on a socket."
2Pick the transport by environment and duplex. Server → WebSocket. Browser → WebRTC.
