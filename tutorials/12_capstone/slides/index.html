Track 1 — The Full Pipeline

The rag_answer() function

def rag_answer(question, k=10, top_n=3,
               use_rerank=True):
    # Step 1: retrieve wide
    candidates = [d.page_content for d in
        vector_store.as_retriever(
            search_kwargs={"k": k}
        ).invoke(question)]

    # Step 2: rerank narrow (or slice)
    if use_rerank:
        contexts = [t for t, _ in
            rerank(question, candidates, top_n)]
    else:
        contexts = candidates[:top_n]

    # Step 3: generate from context
    block = "\n\n".join(
        f"[{i}] {c}"
        for i, c in enumerate(contexts, 1))
    response = chat_llm.invoke(
        RAG_PROMPT.format_messages(
            context=block,
            question=question)).content.strip()
    return {"response": response,
            "retrieved_contexts": contexts}
⚠ Retrieve wide, rerank narrow — the reranker cannot rescue passages the initial search never returned. Widen k before blaming the reranker.

Track 2 — The 12 Metrics

Retriever half vs. Generator half

⚠ A single end-to-end accuracy score hides which half failed. Wrong retrieval needs a different fix than wrong generation — never collapse them into one number.

Track 2 — Retriever Tier

Context Precision & Recall (M7)

LLMContextPrecisionWithReference
Are the retrieved chunks relevant, and are the best ones ranked first?
Precision = quality & ranking of what you fetched
LLMContextRecall
Did retrieval find everything the reference answer needed?
Recall = completeness
High precision + low recall = looks good but misses half of what was needed. Watch for this pattern on multi-hop questions.

Track 2 — Retriever Tier

Entity Recall & Noise Sensitivity (M8)

ContextEntityRecall
Fraction of reference answer's named entities (places, numbers) present in retrieved context.
NoiseSensitivity — LOWER IS BETTER
Fraction of claims in the answer that are wrong and traceable to retrieved noise. 0 is perfect. This metric is inverted — higher means worse.

Track 2 — Generator Tier

Faithfulness (M9)

Every claim in the answer is checked against the retrieved context. The score is the fraction of claims that are supported.

⚠ Faithful ≠ Correct. If retrieval returned a wrong chunk, an answer that loyally repeats it scores 1.0 while being completely wrong. Always pair with Factual Correctness.

Track 2 — Generator Tier

Response Relevancy & Factual Correctness (M9)

ResponseRelevancy: LLM reverse-engineers the question from the answer; cosine similarity to the real question. Rewards on-topic, not right.
FactualCorrectness: claim-level F1 between the answer and the ground-truth reference. The only metric that compares to truth, not context.

Track 2 — Agent Tier

Topic Adherence (M11)

Checks whether the agent stays within its reference_topics. In-scope questions should be answered; out-of-scope should be declined.

scorer = TopicAdherenceScore(
    llm=judge_llm, mode="f1")
score = await scorer.multi_turn_ascore(
    MultiTurnSample(
        user_input=convo,
        reference_topics=[
            "precious metals",
            "metals markets",
            "commodity prices"]))
Precision and recall encode different risks. High-precision agent refuses too much. High-recall agent goes out of bounds. Decide which failure your app can tolerate.

Track 2 — Agent Tier

Tool-Call Accuracy vs. F1 (M11)

ToolCallAccuracy — strict: right tools, right args, right order. One mismatch can score 0. Use as a pass/fail gate.
ToolCallF1 — partial credit: ignores order, gives precision & recall over the call set. Use during development to track progress.
Both metrics match args exactly. metal="Gold" ≠ metal="gold". Write reference calls to match the exact string the agent will produce.

Track 2 — Agent Tier

Agent Goal Accuracy (M11)

Grades the outcome, not the path. Binary: 1 for success, 0 for failure.

WithReference: compare conversation end-state to an ideal outcome you supply.
WithoutReference: judge infers the goal from the conversation itself. More flexible; adds a second layer of LLM judgment (and error).
Binary and blunt — a 1 hides how well the goal was met; a 0 hides how close the agent came. Never use goal accuracy alone.

Track 2 — Judge Biases

LLM as a Judge (M9)

Almost all 12 metrics are scored by a second LLM acting as a grader. We use a different judge model (gemma4:31b-cloud) at temperature 0 — never let the generator grade its own work.

  • Verbosity bias — prefers longer answers
  • Position bias — side-by-side: favours the first option
  • Self-preference — generator inflates its own score
  • Non-determinism — same answer, different scores on re-runs
  • JSON failures → NaN in results table, easy to miss

Track 2 — Multi-Hop Spotlight

The 2 hardest golden questions

Six of the eight golden questions are single-hop (one corpus passage is enough). These two require synthesising two separate passages:

Multi-hop Q1 (silver volatility)
"Why might silver outperform gold in a strong economy but fall faster in a downturn?"
Requires: industrial-demand passage AND the silver-volatility passage
Multi-hop Q2 (bullion vs. ETF)
"For diversification with low counterparty risk, what are the trade-offs of physical bullion versus ETFs?"
Requires: physical-storage passage AND the portfolio-correlation passage
Context recall consistently sags on these two questions — the top-k window may not capture both passages simultaneously. This is a real retrieval limitation, not a bug in the metric. Widening k and reranking helps, but multi-hop retrieval is an open research problem.

Track 3 — MDD & Cautions

Metrics-Driven Development (M6)

MDD is a development discipline, not a one-time grade:

  1. Establish a baseline (use_rerank=False)
  2. Change exactly one thing (turn on reranking)
  3. Recompute on the same test set
  4. Compare — attribute the change to the intervention
Change two things at once and you cannot attribute the win. Keep one variable at a time.

Track 3 — Cautions

Goodhart's Law — the most important caution

When a metric becomes the target,
it stops being a good metric.
If you keep tweaking until one number goes up, you are fitting noise, not improving quality. With eight questions, a 0.02 difference is random variation.
A retriever tuned to maximise context precision on these exact eight questions will overfit their phrasing and fail on new ones.
The right use of metrics: track large, consistent, theory-aligned changes — like the reranking switch — and confirm wins by reading actual answers.

Track 3 — Cautions

⚠ Four more cautions to carry forward

NoiseSensitivity is INVERTED. 0 is perfect; higher is worse. Every other metric rewards a higher number. This column is a trap in a results table.
Faithful ≠ Correct. Faithfulness compares to context, not truth. A faithfully repeated wrong passage scores 1.0. Always pair with FactualCorrectness.
Judge biases are real. Verbosity, position, self-preference, non-determinism. Use a different model for judge and generator, at temperature 0.
Metrics are proxies. A high scoreboard does not guarantee a good system. Keep a human in the loop. Read the actual answers. One number never tells the whole story.
