Track 1 · Why rerank?

Embeddings are broad; answers need to be precise

Bi-encoder (embeddings)
  • Encodes query and doc independently
  • Fast: one dot product per passage
  • Measures general semantic overlap
  • May rank topically related but non-answering passages highly
Cross-encoder (reranker)
  • Takes query and passage together as one input
  • Computes token-level interactions → fine-grained relevance
  • Expensive per doc — run only on the k=10 shortlist

Track 1 · Why rerank?

The retrieve-wide-then-narrow pattern

vector search → k = 10 candidates  →  reranker → top_n = 3 passages → LLM
Why k=10?

Gives the reranker enough candidates to find the truly relevant ones; running the cross-encoder on 10 docs adds only ~200 ms.

Why top_n=3?

A short, high-confidence context block keeps the prompt tight and the generator focused. Three passages is the capstone default — see Module 12 for ablation results.

⚠ CAUTION If the k=10 shortlist does not contain the relevant passage (a recall failure), the reranker cannot surface it. Reranking refines; it does not expand. Track Context Recall separately.

Track 2 · Cohere rerank-v3.5

The rerank() helper

def rerank(query: str, docs: list[str], top_n: int = 3) -> list[tuple[str, float]]:
    """Return the top_n most relevant (doc, score) pairs for query."""
    if not docs:
        return []
    result = co.rerank(
        model="rerank-v3.5",
        query=query,
        documents=docs,
        top_n=top_n,
    )
    return [(docs[r.index], r.relevance_score) for r in result.results]
What comes back
  • r.index — pointer into the original docs list
  • r.relevance_score — float 0–1, higher = more relevant
  • Results are already sorted best-first

Track 2 · Cohere rerank-v3.5

Wiring rerank() into rag_answer()

def rag_answer(
    question: str, k: int = 10, top_n: int = 3, use_rerank: bool = True
) -> dict:
    candidates = [d.page_content for d in base_retriever.invoke(question)]
    if use_rerank:
        contexts = [t for t, _ in rerank(question, candidates, top_n=top_n)]
    else:
        contexts = candidates[:top_n]   # cosine-ranked shortcut (baseline)
    block = "\n\n".join(f"[{i}] {c}" for i, c in enumerate(contexts, 1))
    response = chat_llm.invoke(
        RAG_PROMPT.format_messages(context=block, question=question)
    ).content.strip()
    return {"response": response, "retrieved_contexts": contexts}

The use_rerank=False path slices the first top_n by cosine order — a clean baseline to compare against.

Track 3 · Before / After

When reranking helps — and when it doesn't

Helps most when…
  • Multiple passages are topically similar but only one answers the question
  • The query contains specific entities (e.g., "real interest rates") that the embedding conflates with related terms
  • The corpus is large and semantically dense
Does NOT help when…
  • The relevant passage is not in k=10 (recall failure — reranking is too late)
  • The query is so short/vague that even a cross-encoder has nothing to rerank on
  • Budget or latency constraints prohibit a second API call
